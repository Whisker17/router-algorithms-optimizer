## Private internal upstream reuse

The owner stated the repository is private and wants code reuse to proceed without a licensing approval loop. Agents may independently reuse, adapt and translate upstream code suitable for this private internal research use. Keep pinned source/version records, actual Solidity-to-Python mappings, and required upstream license/notice files as ordinary implementation metadata.

There is no standalone legal-signoff milestone or routine owner approval for otherwise permitted private reuse. The intent is efficient reuse, not a statement that private visibility eliminates upstream terms. Do not strip required notices, change repository visibility, publish/distribute derived code externally, or relicense the whole repository as an incidental implementation step. If an actual source restriction prevents the current use, choose a permitted equivalent while preserving the mandatory behavior; identify a concrete blocker only when that cannot be achieved. Speculative future distribution concerns do not block private implementation.

The SOR source-contract issue remains necessary for source pinning, exact parity scope and goldens. It is not a request to delay implementation for a policy decision the owner has already resolved at the private-research level.

## Runtime acceptance

The owner stated that acceptance runtime does not matter. The former **600-second total-run gate is removed**, including its owner-waiver path. Daily/full wall time remains a measured comparison metric; a slow but correct complete experiment does not fail merely because of duration.

Per-case time/quote limits still prevent runaway work and make experiments comparable. Report timeouts honestly and retain all declared cases, protocols and algorithms. Removing the total-runtime ceiling does not relax integer correctness, protocol fidelity, coverage, source parity, independent verification or reproducibility.
