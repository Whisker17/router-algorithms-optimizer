### 1.3 Disclosures

1. **Two existing tests changed mechanically**, both for the new generated profiles.
   `tests/benchmark/test_algorithm_options.py` `NEW_PROFILES` now lists `config/research_023/profiles/`
   (the 0.2.1/0.2.2 precedent). `tests/routing/test_split_polish_bases.py::test_the_hook_changes_nothing_for_a_shipped_profile`
   skips the shipped profiles whose `split_polish` base is M4/S4/REP: those need the `graph_params_for`
   hook by design. Every other shipped profile is still checked.
2. **Base-configuration audit (static `check`).** For every E1/E2 arm it compares objective, budget,
   measurement, worker, search, the `prepare` params the base itself declares (`search_params` ∪
   `graph_params`) and the base options with the reference arm's resolved profile. `split_polish` also
   hands `path_split` `graph.chunks: 50`, which `path_split` does not declare or read. The per-case
   base-row audit (§2) is the empirical check.
3. **E1-truncated rows** (`not_reached`, 2 cells in each C100 E2 arm) appear as a `not_reached` status
   transition in every comparison: they are kept in the denominators and never scored as matched. That
   includes Q4, where the treatment's own row is E1 truncated.
4. **Stage-T analysis.** `1bfd3f9` had a placeholder analysis module. Stage T's tables were produced by
   the frozen analysis of `60ac764`.
5. **mypy.** `pyproject.toml`'s mypy `files` list is outside this issue's scope and was not extended.
   `uv run mypy tools/research_023/*.py tests/research_023/*.py` is clean under the same strict settings,
   and the tests are in the configured `tests` path.
6. **Wall time** is secondary. Six lanes ran on a shared host, there is no L01 protocol and no timing
   claim. The largest single solve was 101 s (C200), far below the 900 s hard limit.
